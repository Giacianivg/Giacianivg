**Novas rotas em `routes/reservations.js`:**
```
PATCH /api/reservations/:id/checkin    → set status='checkedin', checkin_at=now()
PATCH /api/reservations/:id/checkout   → set status='checkedout', checkout_at=now()
PATCH /api/reservations/:id/cancel     → set status='cancelled'
PATCH /api/reservations/:id            → editar: channel, notes, room_type, dates, guests, amounts
POST  /api/reservations                → criar nova reserva
```

### Frontend — Seções

**1. KPI bar (topo):**
- Chegando hoje | Saindo hoje | Reservas ativas | Taxa de ocupação % | Receita do mês

**2. Filtros:**
- Status (multi-select: confirmada / pendente / checkin / checkout / cancelada)
- Período (date picker range)
- Ala (ALA_A / ALA_B / ALA_C)
- Canal (WhatsApp / Booking / Airbnb / Direto)
- Busca livre (nome, número de reserva)

**3. Timeline visual (Gantt por quarto):**
- Eixo X: dias do mês (igual ao calendar.html)
- Eixo Y: quartos (ALA_A, ALA_B, ALA_C_CASAL)
- Barras coloridas por status (igual às `resv-bar` do calendar)
- Click na barra → abre drawer de detalhe
- Mini-tooltip on hover: hóspede + noites + total

**4. Lista (tab alternativo):**
- Tabela enriquecida: hóspede, quarto, entrada, saída, canal, sinal pago (barra %), total, status
- Ações inline: ✓ confirmar | 🏠 check-in | 🚪 check-out | ✕ cancelar | 📄 voucher

**5. Drawer de detalhe (slide lateral):**
- Header: nome + quarto + status badge
- Timeline do ciclo: Criada → Confirmada → Check-in → Check-out
- Financeiro: total / sinal pago / saldo pendente
- Canal de origem
- Campo notas editável
- Histórico de pagamentos (payments join)
- Botão "Emitir Voucher" → abre vouchers.html?id=XXX ou gera PDF

**6. Modal "Nova Reserva":**
- Campos: hóspede (search em leads), quarto, datas, pessoas, canal, total, sinal
- Cria via POST /api/reservations

## Especificação Técnica — PLU-23 (competitor pricing)

### Migration 014 — nova tabela

```sql
CREATE TABLE competitor_prices (
  id uuid DEFAULT gen_random_uuid() PRIMARY KEY,
  competitor_name text NOT NULL,
  competitor_url text,
  platform text CHECK (platform IN ('booking', 'airbnb', 'direct')),
  date date NOT NULL,
  price numeric(10,2),
  room_type text,
  availability boolean DEFAULT true,
  scraped_at timestamptz DEFAULT now(),
  source text DEFAULT 'apify' CHECK (source IN ('apify', 'manual'))
);

CREATE INDEX idx_competitor_prices_date ON competitor_prices(date);
CREATE INDEX idx_competitor_prices_competitor ON competitor_prices(competitor_name, date);
```

### Novo service: `services/competitor/scraper.js`

```
Responsabilidades:
- Recebe lista de concorrentes (do env ou tabela)
- Chama Apify Actor de hotel scraping para cada URL
- Parseia resultado: nome, preço por data, disponibilidade
- Salva em competitor_prices via supabaseAdmin
- Retorna relatório: N concorrentes scrapeados, N datas, N erros
```

### Cron job (Vercel)

```json
// vercel.json — adicionar:
{
  "crons": [{
    "path": "/api/cron/competitor-prices",
    "schedule": "0 0 * * *"
  }]
}
```

```
api/cron/competitor-prices.js → thin wrapper → scraper.js
```

### Nova rota: `routes/competitor-prices.js`

```
GET /api/competitor-prices?from=YYYY-MM-DD&to=YYYY-MM-DD
  → retorna preços agrupados por data e concorrente

GET /api/competitor-prices/summary?date=YYYY-MM-DD
  → retorna: media_regional, min, max, seu_preco_nesse_dia

POST /api/competitor-prices (manual override)
  → source='manual', body: { competitor_name, date, price }
```

### calendar.html — overlay de preços

Cada célula de dia no Gantt ganha:
```

🏠 Seu preço: R$ 350
📊 Média: R$ 310  (+13% ▲)
🔴 Concorrente A: R$ 280
🟢 Concorrente B: R$ 340
```

Legenda adicional:
- 🔴 Você está X% mais caro que a média
- 🟢 Você está competitivo (±10% da média)
- 🟡 Você está X% mais barato (oportunidade de subir)
