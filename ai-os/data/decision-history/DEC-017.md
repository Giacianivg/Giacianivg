## Features Aprovadas — PAUTA 1 (bookings.html)

### Bloco 1 — Ações (crítico)
- Botão "Nova Reserva" → formulário em drawer lateral
- Inline actions por linha: Confirmar / Check-in / Check-out / Cancelar
- Drawer de detalhe ao clicar na linha (histórico, notas, timeline, ações)

### Bloco 2 — Visibilidade financeira
- Card novo: ADR (ticket médio) + card "Sinal pendente" (soma de saldos em aberto)
- Coluna "Sinal pago" + barra de progresso sinal/total por linha

### Bloco 3 — Operação do dia
- Painel fixo no topo: "Chegando hoje (N)" + "Saindo hoje (N)" com chips clicáveis

### Bloco 4 — Filtros e export
- Filtro por período (date picker range)
- Filtro por quarto / tipo de acomodação
- Filtro por status
- Export CSV

## Arquitetura Aprovada — PAUTA 2 (competitor prices)

```
Vitor define lista de concorrentes (URLs Booking/Airbnb)
           ↓
@price-watcher — novo agente dedicado (não @neil)
           ↓
Apify Actor scrapa preços por data (cron diário 00h Vercel)
           ↓
competitor_prices table no Supabase
  (id, competitor_name, url, date, price, room_type, scraped_at)
           ↓
calendar.html mostra overlay: nome + preço por dia
           ↓
Fallback: interface manual para Vitor inserir preços diretamente
```

### Nova tabela Supabase
```sql
CREATE TABLE competitor_prices (
  id uuid DEFAULT gen_random_uuid() PRIMARY KEY,
  competitor_name text NOT NULL,
  competitor_url text,
  date date NOT NULL,
  price numeric(10,2),
  room_type text,
  scraped_at timestamptz DEFAULT now(),
  source text DEFAULT 'apify' -- 'apify' | 'manual'
);
```

### Agente: @price-watcher
- **Não é o @neil** — Neil faz ads/tráfego. @price-watcher faz inteligência competitiva.
- Responsabilidades: executar scraping via Apify, salvar em Supabase, alertar anomalias
- Roda como cron job, não como agente interativo
